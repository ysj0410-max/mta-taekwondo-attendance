# 🔥 Firebase 실시간 동기화 — 테스트 버전 사용 안내 (v3 · 칸 제한 보안 강화)

경희대MTA태권도 출결관리 프로그램의 **데이터 저장 방식을 Google Drive → Firebase Firestore(실시간 데이터베이스)** 로 바꾸는 **테스트 버전**입니다.
**v2** 에서 **관리자 PC 계정과 출석 태블릿 계정을 완전히 분리**했고, **v3** 에서는 그 위에
① **원생·원비·상담·설정 문서를 관리자 전용으로 고정**, ② **출석 화면용 사본(kioskStudents)과 출결 문서에 들어갈 수 있는 칸을 목록으로 제한**, ③ **출결 위조 방지**(없는 원생 ID·엄뜻한 문서 ID 거부), ④ **화면의 역할 선택이 아니라 서버 `roles/{UID}` 문서로 권한을 잠금** — 네 가지를 더했습니다.

> ⚠️ **운영 버전(v28)은 그대로 있습니다.** 이 테스트 버전은 주소가 다른 별도 폴더(`test-firebase/`)에서만 동작하고, 운영 버전 파일은 한 줄도 건드리지 않았습니다. 마음에 안 들면 주소를 열지 않으면 그만입니다(아래 6번).

## 2. Firebase 프로젝트 만들기 (무료 Spark · 카드 필요 없음)

1. 크롬에서 **https://console.firebase.google.com** 를 엽니다. (구글 계정 `ysj0410@gmail.com` 로그인)
2. **「프로젝트 만들기」** 클릭
3. 프로젝트 이름에 `mta-taekwondo` 입력 → 오른쪽 **프로젝트 ID** 가 `mta-taekwondo-xxxx` 처럼 자동으로 붙습니다. (이 ID를 기억해 두세요)
4. **「계속」** → **「Google 애널리틱스 사용 안 함」** 선택 → **「프로젝트 만들기」**
5. 1분쯤 기다린 뒤 **「계속」** 을 누르면 대시보드가 나옵니다.
6. 화면 아래 프로젝트 이름 옆에 **Spark(무료)** 로 표시되어 있는지 확인합니다. → 여기까지가 **결제 수단을 한 번도 입력하지 않는 단계**입니다.

### 웹 앱 등록 (firebaseConfig 복사)

7. 대시보드에서 **⚙️(톱니) → 프로젝트 설정 → 아래로 스크롤 → 내 앱 → `</>` (웹) 아이콘** 클릭
8. 앱 닉네임에 `MTA 도장 앱` 입력 → **「앱 등록」**
9. **「SDK 설정 및 구성」** 에 나오는 `const firebaseConfig = { ... };` 상자에서 **중괄호 { … } 부분 전체** 를 복사합니다. (예시)

```js
{
  apiKey: "AIzaSy...",
  authDomain: "mta-taekwondo-xxxx.firebaseapp.com",
  projectId: "mta-taekwondo-xxxx",
  storageBucket: "mta-taekwondo-xxxx.appspot.com",
  messagingSenderId: "123456789012",
  appId: "1:123456789012:web:abcdef123456"
}
```

> `const firebaseConfig =` 라는 글자가 함께 복사돼도 괜찮습니다. 앱이 `{ }` 안의 값만 골라 읽습니다.
> 이 값은 **PC와 태블릿에 똑같이** 붙여넣습니다. (같은 프로젝트·같은 도장 ID)

## 3. Firestore · Authentication · 계정 2개 만들기

### 3-1. Firestore 데이터베이스

1. 왼쪽 메뉴 **「빌드」 → 「Firestore Database」** → **「데이터베이스 만들기」**
2. 데이터베이스 ID는 그대로(`(default)`) → **다음**
3. **위치** 는 **`asia-northeast3` (서울)** 선택 → **다음**
4. **보안 규칙** 은 **「프로덕션 모드에서 시작」** 을 고릅니다. (처음엔 아무도 못 읽고 쓰는 상태 → 4번에서 규칙을 붙입니다)
5. **「만들기」** → 30초쯤 기다리면 데이터 탭이 열립니다.

### 3-2. Authentication 켜기 — **이메일/비밀번호만**

1. 왼쪽 메뉴 **「빌드」 → 「Authentication」** → **「시작하기」**
2. **Sign-in method** 탭 → **「이메일/비밀번호」** 클릭 → **사용 설정** 켜기 → **저장**
3. ⚠️ **「익명」(Anonymous) 로그인은 켜지 않습니다.** v2 부터 익명 로그인을 쓰지 않으며 v3 도 그대로입니다. 누가 어느 기기인지 구분할 수 없어 권한을 나눌 수 없기 때문입니다.
   - 또 **두 기기가 같은 계정을 함께 쓰는(공용 관리자 계정) 방식도 없습니다.** 관리자 PC와 태블릿은 반드시 **서로 다른 계정**입니다.

### 3-3. 계정 **두 개** 만들기 (관리자 PC용 / 출석 태블릿용)

**Users** 탭 → **「사용자 추가」** 를 **두 번** 합니다.

| 쓰는 곳 | 이메일 예시 | 비밀번호 | 기억할 이름 |
|---|---|---|---|
| 관리자 PC | `admin@dojang.com` | 8자 이상 (예: 도장에서만 아는 값) | 관리자 계정 |
| 출석 태블릿 | `tablet@dojang.com` | 8자 이상 (관리자와 다른 값) | 태블릿 계정 |

- 두 계정의 **UID**(긴 글자, 예: `Xk3pQ…`)를 각각 복사해 둡니다. 목록에서 사용자를 누르면 **User UID** 가 보입니다.
- ⚠️ **태블릿에 관리자 계정을 쓰면 안 됩니다.** 태블릿은 아이들이 만지는 기기라, 관리자 계정으로 로그인해 두면 그 기기에서 원생 전화번호·생년월일·원비를 읽을 수 있는 상태가 됩니다.

### 3-4. 권한(roles) 문서 **두 개** 만들기 — 첫 관리자는 콘솔에서 직접

1. **Firestore Database → 데이터** 탭
2. **「컬렉션 시작」** → 컬렉션 ID `dojangs` → **다음**
3. 문서 ID 에 **도장 ID**(앱에 넣을 값, 예: `mta-tkd`) 입력 → **저장**
4. 이 문서 안에서 **「컬렉션 시작」** → 컬렉션 ID `roles` → 문서 ID 에 **관리자 계정 UID** 입력
5. 필드 추가: `role` (문자열) = `admin` → **저장**
6. 같은 `roles` 컬렉션에 문서를 **하나 더**: 문서 ID 에 **태블릿 계정 UID** → 필드 `role` (문자열) = `tablet` → **저장**

> 결과
> - `dojangs/mta-tkd/roles/{관리자 UID}` → `role: "admin"`
> - `dojangs/mta-tkd/roles/{태블릿 UID}` → `role: "tablet"`
> 이 두 문서가 없으면 로그인은 되어도 `permission-denied` 가 납니다.
> **v3 부터는 이 문서가 로그인 뒤 자동으로 읽히고, 앱은 그 값으로만 권한이 생깁니다.** 화면에서 고른 역할을 바꿔도 `role` 값이 `admin` 이 아니면 관리자 권한(개인정보·원비·이전)은 생기지 않습니다(4-1 · 6-1 참고).

## 4. 보안 규칙(firestore.rules) 적용하기

1. 이 폴더의 **`firestore.rules`** 파일을 열어 **전체를 복사**합니다.
2. Firebase 콘솔 **Firestore Database → 규칙(Rules)** 탭 클릭
3. 기존 내용을 전부 지우고 **붙여넣기** → **「게시」** → 1분쯤 기다립니다.
4. 규칙이 하는 일 (v3)

| 데이터 | 관리자 PC(`admin`) | 출석 태블릿(`tablet`) |
|---|---|---|
| `students` 원생 전체 정보(전화·생년월일·티콘ID·특이사항·원비) | 읽기·쓰기 | **전면 차단** |
| `kioskStudents` 출석 화면용 최소 정보(이름·부서·수업·띠·상태) | 읽기·쓰기 | **읽기만** |
| `attendanceEvents` 출결 | 읽기·쓰기 | **읽기 + 새로 만들기만**(수정·삭제 불가) |
| `tuition` 원비 · `counsel` 상담 · `shuttle` 차량 · `coupons` 쿠폰 | 읽기·쓰기 | **전면 차단** |
| `meta/kioskConfig` 출석 화면 최소 설정 | 읽기·쓰기 | **읽기만** |
| `meta/settings`·`feeTable`·`smsTemplates`·`logs`·`admin` 등 나머지 설정 | 읽기·쓰기 | **전면 차단** |
| `roles` 권한 문서 | 자기 것 읽기, 만들기·수정 | 자기 것 읽기만 |
| 로그인하지 않은 사람 | 전부 차단 | 전부 차단 |

- `kioskStudents` 문서에는 **`phone`·`birthDate`·`tconId`·`note`·`tuitionDay` 등 개인정보 칸이 들어가면 규칙이 저장 자체를 거부**합니다(관리자 기기가 실수로 보내도 막힘). v3 부터는 한 걸음 더 나가서 **정해진 칸 목록(`id`·`name`·`division`·`course`·`belt`·`status` + 엔진 메타) 밖의 칸이 하나라도 있으면 거부**합니다.
- **출결 문서 칸 제한**: `date`·`studentId`·`kind`·`time`·`eventId`·`source`·`manual`·`deviceId` + 엔진 메타 4개만 허용합니다. 임의의 칸을 끼워 넣으면 거부됩니다.
- **태블릿의 출결 만들기 3중 검사**: ① `kind`는 `in`/`out`, `date`는 `YYYY-MM-DD`, `time`은 `HH:MM` 형식 ② 그 도장에 **실제로 있는 원생(`kioskStudents` 문서가 있는 원생)** 이어야 함 ③ 문서 ID가 **`{날짜}_{원생ID}_{in|out}` 와 정확히 같아야** 함 → 없는 원생 ID나 엄뚱한 문서 ID 로는 출결을 위조할 수 없습니다.
- ⚠️ 규칙의 `get()`·`exists()` 은 문서 읽기로 계산됩니다. 하루 사용량을 볼 때 참고하세요(무료 5만 건/일).

### 4-1. v3 규칙·코드 대조 확인(직접 해보실 수 있는 것)

- 이 폴더의 `firestore.rules` 는 앱이 실제로 쓰는 칸과 **한 칸도 다르지 않은 목록**을 쓰고 있습니다. (앱의 출결 문서: `date`·`studentId`·`kind`·`time`·`eventId`·`source`·`manual`·`deviceId` + `_ver`·`_updatedAt`·`_updatedBy`·`_fieldMeta`)
- 그래서 규칙을 게시한 뒤 **태블릿에서 출석을 찍으면 그대로 저장**됩니다. 만약 태블릿 출석이 `permission-denied` 로 실패하면, 그 원생이 **관리자 PC의 「이전 실행」으로 `kioskStudents` 사본이 만들어진 뒤**인지 먼저 확인해 주세요.

> 규칙을 바꾼 뒤 앱에서 **「🔌 연결 테스트」** 를 눌러 `연결됨` 이 나오면 정상입니다.
> `permission-denied` 가 나오면 ① 로그인 여부 ② `roles/{UID}` 문서의 `role` 값 ③ 도장 ID 철자를 확인하세요.

## 5. 기존 데이터 이전하기 (운영 데이터 → Firestore)

준비물: **운영 버전에서 받아 둔 전체 백업 파일**(`mta-taekwondo-backup-....json`) 또는 지금 쓰는 기기의 데이터.

1. 테스트 주소를 **관리자 PC**에서 엽니다 → **🔐 관리자 계정** 탭 → 아래로 스크롤 → **🔥 Firebase 실시간 동기화** 패널
2. **도장 ID** 에 3번에서 쓴 값(`mta-tkd`)을 입력
3. **이 기기 역할** = `관리자 PC`
4. **연결 모드** = `🔥 실제 Firebase`
5. **firebaseConfig** 칸에 2번에서 복사한 `{ … }` 를 붙여넣기
6. **「설정 저장 · 연결」** → 잠시 뒤 **「🔌 연결 테스트」** 로 `✅ 연결됨` 확인
7. **👨‍💼 관리자 PC 계정** 칸에 **관리자 계정 이메일·비밀번호** 입력 → **관리자로 로그인** → `✅ 관리자 PC 계정으로 로그인했습니다` 확인
   - 이 순간 앱이 **`dojangs/mta-tkd/roles/{내 UID}` 를 직접 읽어** 관리자인지 확인합니다. 확인되지 않으면 🔒「역할 확인 전」으로 잠기고 **서버로 아무것도 보내지 않습니다**(6-1 참고).
8. (운영 데이터를 이 기기에 먼저 올려야 한다면) **💾 도장 데이터 전체 백업 / 복원** → **「⬆ 백업 파일로 복원」** 으로 백업 파일을 먼저 불러옵니다. → 이때 한 번 더 확인창이 뜹니다.
9. **📤 기존 데이터를 Firestore로 안전 이전** → **「🔍 미리보기」**
   - 표에 **저장 키 전부**(`tdk.students.v1` … `tdk.couponTypes.v1`, 16개)와 건수가 나옵니다.
   - `faces`(원생 얼굴) · `adminFace`(관리자 얼굴) 는 **「🚫 기기 로컬 전용 (보내지 않음)」** 으로 표시됩니다.
   - **📱 출석 화면용 최소 정보(kioskStudents)** 는 원생 명단에서 **자동으로 만들어지는 사본**이라 따로 `자동 생성` 표시와 함께 건수가 나옵니다. (원생 수와 같은 건수, 예: 원생 42명 → 42건)
10. 표를 확인하고 **「📤 Firestore로 이전 실행」** → 확인창에서 **확인**
    - 완료되면 `✅ 이전 완료 — 새로 저장 N건 · 건너뜀 M건` 이 나오고, 아래에 **키별 저장 건수**가 표시됩니다.
    - **이미 Firestore에 있는 문서는 덮어쓰지 않습니다.** 여러 번 눌러도 안전합니다.
11. Firebase 콘솔 **Firestore → 데이터** 에서 `dojangs/mta-tkd/students`·`kioskStudents` 등이 생겼는지 눈으로 확인합니다.

### 5-1. 이후 원생 정보를 고치면

- 관리자 PC에서 원생을 **저장·수정·삭제**하면 `students` 문서와 함께 **`kioskStudents` 사본도 자동으로 갱신**됩니다(이름·부서·수업·띠·상태만).
- 원생을 삭제하면 사본도 함께 삭제 표시됩니다.
- 태블릿에는 **몇 초 안에** 이름·띠·상태 변경이 반영됩니다. 전화번호·특이사항은 **애초에 태블릿으로 가지 않습니다.**

## 6. 출석 태블릿 준비 (v3 — 태블릿 계정)

1. 태블릿에서 테스트 주소를 엽니다.
2. 관리자 화면 → Firebase 패널 → **도장 ID**(같은 값) · **이 기기 역할 = `출석 태블릿`** · 모드 `🔥 실제 Firebase` · **같은 firebaseConfig** 붙여넣기 → **설정 저장 · 연결**
3. **📱 출석 태블릿 계정** 칸에 **태블릿 계정 이메일·비밀번호**로 **태블릿으로 로그인**
   - `✅ 출석 태블릿 계정입니다` 가 나오면 정상입니다.
   - **관리자 계정으로 로그인하면 이 기기는 🔒 태블릿 권한으로 잠깁니다**(경고가 표시됩니다) — 태블릿 전용 계정으로 다시 로그인하세요.
4. 왼쪽 아래 표시가 **🟢 실시간 연결됨** 인지 확인합니다.
5. PC에서 원생 이름·띠를 고치면 태블릿에 몇 초 안에 반영됩니다.

### 6-1. 화면의 「이 기기 역할」과 실제 권한 (v3 핵심)

패널의 **「이 기기 역할」 드롭다운은 안내·연습용**입니다. 실제 권한은 **로그인한 계정의 서버 `roles/{UID}` 문서**가 정합니다.

| 서버 `roles/{UID}` | 화면 드롭다운 | 이 기기가 실제로 하는 일 |
|---|---|---|
| `admin` | 관리자 PC | ✅ 모든 데이터 읽기·쓰기 · 이전 |
| `admin` | 출석 태블릿 | ⚠️ **태블릿으로만** 동작(더 제한적인 쪽) — 원생 개인정보는 다운로드되지 않음 |
| `tablet` | 관리자 PC | ❌ **관리자 권한 없음** — 태블릿으로만 동작. 원생·원비·설정은 올리지도 읽지도 못하고, 「이전 실행」도 잠깁니다 |
| `tablet` | 출석 태블릿 | ✅ 출석 화면 + 출결만 |
| 문서 없음 / 로그인 전 | 무엇이든 | 🔒 **역할 미확인으로 잠김** — 출결도 서버로 보내지 않고 기기에 모아 둡니다(로그인하면 바로 올라갑니다) |

- 락이 걸리면 패널에 🔒 안내가 뜨고, 데이터 이전 버튼은 비활성화됩니다.
- **드롭다운을 바꾸거나 「설정 저장」을 다시 눌러도 서버 역할이 바뀌지 않으므로 권한이 올라가지 않습니다.** 권한을 바꾸려면 Firebase 콘솔에서 `roles/{UID}` 의 `role` 값을 고치세요.

### 태블릿이 읽을 수 있는 것 / 없는 것

| 태블릿에서 | 결과 |
|---|---|
| 출석 화면(이름·띠·부서·수업·상태) | ✅ 보임 |
| 출결 기록 | ✅ 보임 |
| 원생 전화번호·생년월일·티콘ID·특이사항 | ❌ **없음**(서버가 막음) |
| 원비·상담·차량·쿠폰 | ❌ **없음**(서버가 막음) |
| 설정(문자 웹훅 URL·문구·관리자 해시) | ❌ **없음**(서버가 막음) |

- ⚠️ **태블릿에서 「이전 실행」을 누르지 마세요.** (역할이 tablet이면 버튼이 잠깁니다)
- 얼굴 특징값(`tdk.faces.v1`)은 원래 **기기 로컬 전용**입니다. 태블릿을 바꾸면 얼굴은 그 태블릿에서 다시 등록해야 합니다.

### 6-2. 태블릿에서 찍은 출석의 보호자 문자는?

태블릿에는 보호자 전화번호가 없습니다(개인정보 분리). 그래서 **켜져 있는 관리자 PC가 태블릿의 출석을 받아 대신 문자를 보냅니다.**

- 태블릿 화면에는 발송 로그가 **「관리자 PC가 발송」** 으로 표시됩니다.
- 관리자 PC가 켜져 있고 「자동발송」이 켜져 있어야 실제 문자가 나갑니다.
- 관리자 PC가 꺼져 있던 동안의 출석은 **문자가 나가지 않을 수 있습니다**(한 시간이 지난 기록은 몰아 보내지 않습니다 — 학부모님께 늦은 문자가 가지 않도록).
- 관리자 PC의 키오스크에서 직접 찍은 출석은 지금처럼 그 PC가 바로 보냅니다.

## 8. 평소 사용 — 무엇이 자동으로 되나요?

| 상황 | 동작 |

## 10. 무료(Spark) 한도와 비용 — **이 기기 숫자는 합산이 아닙니다**

| 항목 | 무료 한도(하루) | 이 앱의 쓰임 |
|---|---|---|
| 문서 읽기 | 50,000 | 화면을 열 때, 실시간 변경 받을 때 |
| 문서 쓰기 | 20,000 | 출결 1건, 원생 1명 수정 = 각 1건 |
| 문서 삭제 | 20,000 | 원생 삭제 등 |
| 저장 용량 | 1 GiB | 원생 100명 × 1년 출결 ≈ 10MB 수준 |

- 패널의 게이지는 **「이 기기 추정 사용량 (PC·태블릿 합산 아님)」** 입니다. 관리자 PC에서 센 숫자에는 **태블릿이 쓴 양이 빠져 있습니다.**
- **프로젝트 전체 사용량**은 Firebase 콘솔 → **Firestore → 사용량** 탭에서 확인하세요. (패널 안의 **「Firebase 콘솔 · Firestore 사용량 열기」** 링크)
- 관원 100명 기준 하루 **수백 건** 수준이라 무료 한도에 크게 못 미칩니다.
- 한도를 넘으면 **그날만** 동기화가 멈추고(태평양 시간 자정에 초기화), **자동 결제는 절대 되지 않습니다.**

## 11. 자주 생기는 문제

| 증상 | 해결 |
|---|---|
| `permission-denied` | ① 로그인 상태 ② `dojangs/{도장ID}/roles/{UID}` 문서와 `role` 값(admin/tablet) ③ 규칙 게시 여부 |
| 태블릿에서 `permission-denied` | **정상**입니다 — 태블릿은 `students`·`tuition`·`counsel`·`meta` 를 읽을 수 없습니다. 태블릿 역할로는 `kioskStudents`·`attendanceEvents`·`meta/kioskConfig` 만 읽습니다. |
| 태블릿에 원생이 안 보임 | 「설정 저장 · 연결」 후 10초 대기 → 관리자 PC에서 「🔍 미리보기」·「이전 실행」을 했는지 확인(그래야 `kioskStudents` 가 생깁니다) |
| 태블릿에 원생 이름은 보이는데 전화번호가 없음 | **정상**입니다(개인정보 분리). 전화번호는 관리자 PC에만 있습니다. |
| 태블릿 출석 후 문자가 안 옴 | ① 관리자 PC가 켜져 있는지 ② 관리자 PC의 문자 자동발송이 켜져 있는지 ③ 출석이 한 시간 안의 것인지 |
| 태블릿에 관리자 계정으로 로그인함 | 이 기기는 **태블릿 권한으로만 동작**합니다(경고 표시). 로그아웃하고 태블릿 계정으로 다시 로그인하세요. |
| 🔒 「역할 미확인 · 로그인 필요」 로 보임 | 역할에 맞는 계정으로 로그인하세요. 로그인 전에는 서버로 아무것도 보내지 않습니다(기기에 모아 둠). |
| 드롭다운을 관리자로 바꿔도 관리자 기능이 없음 | **정상**입니다 — 권한은 서버 `roles/{UID}` 의 `role` 값이 정합니다. 콘솔에서 고쳐야 합니다. |
| 태블릿 출석이 `permission-denied` | ① 관리자 PC에서 「이전 실행」을 해서 그 원생의 `kioskStudents` 문서가 있는지 ② 원생 ID에 공백·마침표 같은 특수문자가 없는지(문서 ID로 쓸 수 있는 글자만 허용) |
| `미연결(로컬 모드)` 그대로 | 패널에서 모드가 `🔥 실제 Firebase` 인지, firebaseConfig를 저장했는지 확인 |
| 아무 것도 동기화되지 않음 | 도장 ID가 PC와 태블릿에서 **같은지** 확인 (다르면 서로 다른 방에 저장됩니다) |
| 비밀번호를 잊음 | Firebase 콘솔 → Authentication → Users → 해당 사용자 → 비밀번호 재설정 |
| 실수로 잘못 이전함 | Firestore 문서는 콘솔에서 지울 수 있고, 기기 데이터는 그대로입니다. 다시 「이전 실행」하면 됩니다. |

## 12. 먼저 해 볼 연습(권장) — Firebase 없이 3분

1. 테스트 주소를 엽니다 → 관리자 로그인(`admin` / `0000`)
2. **🔥 Firebase 실시간 동기화** 패널 → **「🧪 모의 모드로 켜기」**
3. 같은 브라우저에서 이 주소를 **탭 하나 더** 엽니다(같은 모의 데이터를 공유).
4. 한쪽에서 원생 메모를 고치고, 다른 쪽에서 같은 원생의 띠를 고쳐 보세요 → **둘 다 남습니다.**
5. 한쪽에서 출석을 찍어 보세요 → 다른 쪽 「오늘 출석」에 바로 나타납니다.
6. 패널의 **📊 사용량**·**📨 전송 대기**·**📤 미리보기**를 눌러 숫자를 확인합니다. (미리보기 표에서 `kioskStudents` 자동 생성 건수도 함께 보입니다)

> 🧪 모의 모드는 **로그인 없이** 패널의 「이 기기 역할」만 바꿔 두 역할을 모두 연습할 수 있습니다(서버가 없는 연습장이라 서버 역할 잠금은 적용되지 않습니다). 실제 Firebase 모드에서는 6-1 처럼 **서버 `roles` 기준으로 잠깁니다.**

연습이 끝나면 모드를 `미연결` 로 바꾸면 됩니다(연습 데이터는 이 기기에만 남습니다).
