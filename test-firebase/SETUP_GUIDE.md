## 2. Firebase 프로젝트 만들기 (무료 Spark · 카드 필요 없음)

1. 크롬에서 **https://console.firebase.google.com** 를 엽니다. (구글 계정 `ysj0410@gmail.com` 로그인)
2. **「프로젝트 만들기」** 클릭
3. 프로젝트 이름에 `mta-taekwondo` 입력 → 오른쪽 **프로젝트 ID** 가 `mta-taekwondo-xxxx` 처럼 자동으로 붙습니다. (이 ID를 기억해 두세요)
4. **「계속」** → **「Google 애널리틱스 사용 안 함」** 선택 → **「프로젝트 만들기」**
5. 1분쯤 기다린 뒤 **「계속」** 을 누르면 대시보드가 나옵니다.
6. 화면 아래 프로젝트 이름 옆에 **Spark(무료)** 로 표시되어 있는지 확인합니다. → 여기까지가 **결제 수단을 한 번도 입력하지 않는 단계**입니다.

### 웹 앱 등록 (firebaseConfig 복사)

7. 대시보드에서 **⚙️(톱니) → 프로젝트 설정 → 아래로 스크롤 → 내 앱 → `</>` (웹) 아이콘** 클릭
8. 앱 닉네임에 `MTA 도장 앱` 입력 → **「앱 등록」**
9. **「SDK 설정 및 구성」** 에 나오는 `const firebaseConfig = { ... };` 상자에서 **중괄호 { … } 부분 전체** 를 복사합니다. (예시)

```js
{
  apiKey: "AIzaSy...",
  authDomain: "mta-taekwondo-xxxx.firebaseapp.com",
  projectId: "mta-taekwondo-xxxx",
  storageBucket: "mta-taekwondo-xxxx.appspot.com",
  messagingSenderId: "123456789012",
  appId: "1:123456789012:web:abcdef123456"
}
```

> `const firebaseConfig =` 라는 글자가 함께 복사돼도 괜찮습니다. 앱이 `{ }` 안의 값만 골라 읽습니다.

## 3. Firestore 데이터베이스 만들기

1. 왼쪽 메뉴 **「빌드」 → 「Firestore Database」** → **「데이터베이스 만들기」**
2. 데이터베이스 ID는 그대로(`(default)`) → **다음**
3. **위치** 는 **`asia-northeast3` (서울)** 선택 → **다음**
4. **보안 규칙** 은 **「프로덕션 모드에서 시작」** 을 고릅니다. (처음엔 아무도 못 읽고 쓰는 상태 → 4번에서 규칙을 붙입니다)
5. **「만들기」** → 30초쯤 기다리면 데이터 탭이 열립니다.

### Authentication 켜기

1. 왼쪽 메뉴 **「빌드」 → 「Authentication」** → **「시작하기」**
2. **Sign-in method** 탭 → **「이메일/비밀번호」** 클릭 → **사용 설정** 켜기 → **저장**
3. 같은 화면에서 **「익명」** 이 필요하면 켜 둡니다(태블릿을 익명 계정으로 쓸 때). 이 안내서는 **이메일 계정 하나**로 PC와 태블릿을 모두 쓰는 방법을 권합니다.
4. **Users** 탭 → **「사용자 추가」** → 관리자 이메일(예: `dojang@ysj0410.com`)과 비밀번호(8자 이상)를 넣고 **저장**. **이 이메일·비밀번호가 앱의 「🔑 관리자 로그인」에 쓰는 값입니다.**
5. 방금 만든 사용자의 **UID** (긴 글자, 예: `Xk3pQ...`)를 복사해 둡니다.

### 권한(roles) 문서 만들기 — 첫 관리자 1명은 콘솔에서 직접

1. **Firestore Database → 데이터** 탭
2. **「컬렉션 시작」** → 컬렉션 ID `dojangs` → **다음**
3. 문서 ID 에 **도장 ID**(앱에 넣을 값, 예: `mta-tkd`) 입력 → **저장**
4. 이 문서 안에서 **「컬렉션 시작」** → 컬렉션 ID `roles` → 문서 ID 에 **위에서 복사한 UID** 입력
5. 필드 추가: `role` (문자열) = `admin` → **저장**

> 결과 경로: `dojangs/mta-tkd/roles/Xk3pQ...` → `role: "admin"`
> 태블릿을 별도 계정으로 쓸 때는 같은 방법으로 `role: "tablet"` 문서를 하나 더 만듭니다.

## 4. 보안 규칙(firestore.rules) 적용하기

1. 이 폴더의 **`firestore.rules`** 파일을 열어 **전체를 복사**합니다.
2. Firebase 콘솔 **Firestore Database → 규칙(Rules)** 탭 클릭
3. 기존 내용을 전부 지우고 **붙여넣기** → **「게시」** → 1분쯤 기다립니다.
4. 규칙이 하는 일
   - 로그인 안 한 사람: **읽기·쓰기 전부 차단**
   - 관리자(role=admin): 모든 데이터 읽기·쓰기
   - 출석 태블릿(role=tablet): 원생 이름·띠·출결만 읽고, **출결 이벤트 새로 만들기만** 가능 (원생 수정·삭제, 원비·상담 열람, 설정 변경 불가)
5. ⚠️ 규칙의 `get()` 은 문서 읽기 1회로 계산됩니다. 하루 사용량을 볼 때 참고하세요(무료 5만 건/일).

> 규칙을 바꾼 뒤 앱에서 **「🔌 연결 테스트」** 를 눌러 `연결됨` 이 나오면 정상입니다.
> `permission-denied` 가 나오면 ① 로그인 여부 ② `roles/{UID}` 문서의 `role` 값 ③ 도장 ID 철자를 확인하세요.

## 5. 기존 데이터 이전하기 (운영 데이터 → Firestore)

준비물: **운영 버전에서 받아 둔 전체 백업 파일**(`mta-taekwondo-backup-....json`) 또는 지금 쓰는 기기의 데이터.

1. 테스트 주소를 PC에서 엽니다 → **🔐 관리자 계정** 탭 → 아래로 스크롤 → **🔥 Firebase 실시간 동기화** 패널
2. **도장 ID** 에 3번에서 쓴 값(`mta-tkd`)을 입력
3. **이 기기 역할** = `관리자 PC`
4. **연결 모드** = `🔥 실제 Firebase`
5. **firebaseConfig** 칸에 2번에서 복사한 `{ … }` 를 붙여넣기
6. **「설정 저장 · 연결」** → 잠시 뒤 **「🔌 연결 테스트」** 로 `✅ 연결됨` 확인
7. **🔑 관리자 로그인** 에 3번에서 만든 이메일·비밀번호 입력 → **로그인** → `✅ 관리자로 로그인했습니다` 확인
8. (운영 데이터를 이 기기에 먼저 올려야 한다면) **💾 도장 데이터 전체 백업 / 복원** → **「⬆ 백업 파일로 복원」** 으로 백업 파일을 먼저 불러옵니다. → 이때 한 번 더 확인창이 뜹니다.
9. **📤 기존 데이터를 Firestore로 안전 이전** → **「🔍 미리보기」**
   - 표에 **16개 저장 키 전부**와 건수가 나옵니다.
   - `faces`(원생 얼굴) · `adminFace`(관리자 얼굴) 는 **「🚫 기기 로컬 전용 (보내지 않음)」** 으로 표시됩니다.
10. 표를 확인하고 **「📤 Firestore로 이전 실행」** → 확인창에서 **확인**
    - 완료되면 `✅ 이전 완료 — 새로 저장 N건 · 건너뜀 M건` 이 나옵니다.
    - **이미 Firestore에 있는 문서는 덮어쓰지 않습니다.** 여러 번 눌러도 안전합니다.
11. Firebase 콘솔 **Firestore → 데이터** 에서 `dojangs/mta-tkd/students` 등이 생겼는지 눈으로 확인합니다.

### 태블릿 준비

1. 태블릿에서 테스트 주소를 엽니다.
2. 관리자 화면 → Firebase 패널 → **도장 ID**(같은 값) · **이 기기 역할 = `출석 태블릿`** · 모드 `🔥 실제 Firebase` · **같은 firebaseConfig** 붙여넣기 → **설정 저장 · 연결**
3. **🔑 관리자 로그인**: 태블릿도 위에서 만든 **관리자 이메일**로 로그인하면 가장 간단합니다. (별도 계정을 쓰려면 `roles/{UID}` 에 `role: "tablet"` 을 만들어 그 계정으로 로그인 — 이 경우 원생·원비·상담 수정은 규칙이 막습니다.)
4. 왼쪽 아래 표시가 **🟢 실시간 연결됨** 인지 확인합니다.
5. PC에서 원생 이름을 고치면 태블릿에 몇 초 안에 반영됩니다. 반대도 마찬가지입니다.

> 💡 **태블릿에서는 「이전 실행」을 누르지 마세요.** (역할이 tablet이면 버튼이 잠깁니다)

## 7. 평소 사용 — 무엇이 자동으로 되나요?

| 상황 | 동작 |
|---|---|
| PC에서 원생 메모 수정, 태블릿에서 같은 원생 띠 수정 (동시) | **두 변경 모두 살아남습니다** (필드 단위 병합). 서로의 수정을 덮어쓰지 않습니다. |
| 태블릿에서 출석 찍기 | `attendanceEvents/{날짜}_{원생ID}_in` 문서 1건이 만들어지고 PC에 실시간 반영. 같은 출석을 두 번 찍어도 문서는 1건입니다. |
| 인터넷이 끊김 | 기록은 **이 기기(tdk.fbOutbox.v1)에 「전송 대기(오프라인)」** 로 쌓입니다. 배지가 🟡 오프라인 대기로 바뀝니다. |
| 인터넷 복구 | 자동으로 다시 보냅니다. **서버 저장이 확인된 뒤에만** 대기 목록에서 지웁니다. |
| 무료 한도 80% | 패널에 노란 경고 |
| 무료 한도 100% | **자동 유료 전환 없이** 동기화만 멈추고, 기록은 이 기기에 보관. 패널에 빨간 안내(Google Drive 백업 권장) |
| 앱을 껐다 켜기 | 대기 중이던 기록은 그대로 남아 있어 이어서 전송합니다. |

### 대기 목록 · 전송 결과 확인
패널의 **📨 전송 대기 · 최근 동기화** → **「대기 목록 보기」**
- `전송 대기` : 아직 보내지 못한 기록
- `전송 실패` : 보내다 실패(인터넷·권한) — **「실패 재시도」** 로 다시 보냅니다
- `서버 확인 대기` : 보냈지만 서버 확인(ACK)을 못 받은 상태 — 큐에 그대로 남아 있습니다

## 8. 얼굴인식 데이터는 어디에도 안 보냅니다

- `tdk.faces.v1`(원생 얼굴 128차원) · `tdk.adminFace.v1`(관리자 얼굴)
- 이 두 가지는 **어떤 경우에도 Firestore로 전송되지 않습니다.** (미리보기 표에도 「기기 로컬 전용」으로 표시되고, 이전 실행에서도 빠집니다)
- 따라서 **태블릿을 바꾸면 얼굴은 다시 등록**해야 합니다. 명단·출결·원비는 자동으로 따라옵니다.
- 얼굴까지 옮기고 싶으면 지금처럼 **💾 전체 백업 파일**로 옮기세요.

## 10. 자주 생기는 문제

| 증상 | 해결 |
|---|---|
| `permission-denied` | ① 로그인 상태 확인 ② `dojangs/{도장ID}/roles/{UID}` 문서와 `role` 값 ③ 규칙 게시 여부 |
| `미연결(로컬 모드)` 그대로 | 패널에서 모드가 `🔥 실제 Firebase` 인지, firebaseConfig를 저장했는지 확인 |
| 아무 것도 동기화되지 않음 | 도장 ID가 PC와 태블릿에서 **같은지** 확인 (다르면 서로 다른 방에 저장됩니다) |
| 태블릿에 원생이 안 보임 | 「설정 저장 · 연결」 후 10초 대기, 그래도 안 되면 「🔍 미리보기」로 데이터가 있는지 확인 |
| 비밀번호를 잊음 | Firebase 콘솔 → Authentication → Users → 해당 사용자 → 비밀번호 재설정 |
| 실수로 잘못 이전함 | Firestore 문서는 콘솔에서 지울 수 있고, 기기 데이터는 그대로입니다. 다시 「이전 실행」하면 됩니다. |

## 11. 먼저 해 볼 연습(권장) — Firebase 없이 3분

1. 테스트 주소를 엽니다 → 관리자 로그인(`admin` / `0000`)
2. **🔥 Firebase 실시간 동기화** 패널 → **「🧪 모의 모드로 켜기」**
3. 같은 브라우저에서 이 주소를 **탭 하나 더** 엽니다(같은 모의 데이터를 공유).
4. 한쪽에서 원생 메모를 고치고, 다른 쪽에서 같은 원생의 띠를 고쳐 보세요 → **둘 다 남습니다.**
5. 한쪽에서 출석을 찍어 보세요 → 다른 쪽 「오늘 출석」에 바로 나타납니다.
6. 패널의 **📊 사용량**·**📨 전송 대기**·**📤 미리보기**를 눌러 숫자를 확인합니다.

연습이 끝나면 모드를 `미연결` 로 바꾸면 됩니다(연습 데이터는 이 기기에만 남습니다).
